# Обзор

`opengrok-mcp` — это MCP (Model Context Protocol) сервер, который соединяет
LLM-клиентов с поиском по коду [OpenGrok](https://oracle.github.io/opengrok/).
Проект создан для кодовых баз масштаба **AOSP 15** — десятки миллионов строк
кода в сотнях проектов — и решает проблемы с задержками, объёмом результатов
и аутентификацией, характерные для такого масштаба.

Далее: [Установка →](./installation.md)

---

## Какую проблему решает?

LLM-агентам (Claude Desktop, Codex и др.) нужно искать и читать исходный код
в больших монорепозиториях. OpenGrok предоставляет REST API для полнотекстового
поиска, навигации по файлам, истории и аннотации, но его «сырой» API неудобен для LLM:

- HTML-теги в результатах (`<b>совпадение</b>`) нужно удалять
- Пагинацию нужно обрабатывать и сообщать LLM через подсказки `has_more`
- Большие наборы результатов требуют ограничения и кэширования для снижения задержек
- API имеет особенности (`null` в тегах, пустые `lineNumbers`), требующие нормализации
- Необходимо настраивать аутентификацию и TLS с корпоративными сертификатами

`opengrok-mcp` упаковывает всё это в 25 аккуратных MCP-инструментов с корректной
обработкой ошибок, ограничением частоты запросов и форматированием результатов.

## Возможности

### 25 инструментов MCP — полное покрытие OpenGrok REST API

| Категория | Инструменты |
|---|---|
| Поиск (7) | `search_code`, `search_definition`, `search_references`, `search_file_path`, `search_history`, `advanced_search`, `suggest` |
| Файлы (5) | `get_file_content`, `get_file_definitions`, `get_file_genre`, `get_history`, `get_annotation` |
| Навигация (8) | `list_directory`, `list_indexed_projects`, `list_all_projects`, `list_groups`, `get_group_projects`, `list_project_files`, `list_project_repos`, `get_project_property` |
| Система (5) | `get_repo_property`, `get_suggest_config`, `get_index_time`, `get_opengrok_version`, `health_check` |

Каждый инструмент описывает свои параметры через JSON Schema (schemars),
поэтому LLM-клиенты автоматически знают ожидаемые входные и выходные данные —
ручной промпт-инжиниринг не требуется.

### Двойной транспорт

| Режим | Применение |
|---|---|
| **stdio** | Прямой запуск процесса: `docker exec`, локальный подпроцесс Claude Desktop, отладка |
| **Streamable HTTP** | Сетевое развёртывание: удалённый сервер, несколько клиентов, health checks, метрики |

Режим `both` запускает stdio и HTTP одновременно.

### Гибкая аутентификация

| Режим | Описание |
|---|---|
| `token` | Bearer-токен из переменной окружения |
| `basic` | HTTP Basic Auth (логин/пароль из переменных окружения) |
| `none` | Без аутентификации — для открытых инстансов |

Учётные данные **никогда** не хранятся в файле конфигурации — только имена
переменных окружения.

### TLS с пользовательскими сертификатами

Поддерживаются корпоративные и самоподписанные CA-сертификаты через:

- `OPENGROK_CA_CERT` / `SSL_CERT_FILE` — путь к PEM-файлу
- `SSL_CERT_DIR` — директория с файлами сертификатов
- Директория `config/certs/` (монтируется только для чтения в Docker)

### Защита от DNS rebinding

В режиме HTTP rmcp проверяет заголовок `Host` по настраиваемому списку
`allowed_hosts`. Запросы с несовпадающим хостом получают **403 Forbidden**.
Это предотвращает атаки DNS rebinding при сетевом доступе к серверу.

### Оптимизации для кодовых баз масштаба AOSP

| Возможность | Назначение |
|---|---|
| **Очистка HTML-тегов** | Удаляет `<b>` из результатов поиска — вывод чище для LLM |
| **Ограничение результатов** | `max_hits_per_file` ограничивает строки совпадений в файле |
| **Кэш в памяти** | TTL-кэш с настраиваемым размером, исключает повторные вызовы API |
| **Rate limiting** | Алгоритм token bucket защищает OpenGrok от перегрузки |
| **Подсказки пагинации** | Поле `has_more` в ответах сообщает LLM о наличии дополнительных результатов |

### Health и метрики

| Эндпоинт | Назначение |
|---|---|
| `/healthz` | Живучесть — всегда возвращает 200, если процесс запущен |
| `/readyz` | Готовность — 200, когда конфигурация загружена и OpenGrok доступен |
| `/metrics` | Метрики в формате Prometheus (счётчики запросов, задержки, статистика кэша) |

### Docker

Многоэтапная сборка, образ на базе Alpine размером **~35 МБ**. Docker Compose
для локальной разработки и удалённого деплоя.
